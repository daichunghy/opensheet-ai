# Inventory and revenue example

This example turns a typed `kpi-threshold.v1` intent into a reviewable
inventory/revenue table. It uses only the existing public compiler and memory
adapter exports.

All four metrics use a lower-bound target: a larger `actual` value is better.
The `Gap` and `Status` cells are deterministic literal values generated by the
compiler; they are not spreadsheet formulas.

## Run it

Build the local package first, then print the deterministic artifact:

```bash
npm run build
node examples/inventory-revenue/preview.mjs > /tmp/inventory-revenue-preview.json
```

The checked-in [preview artifact](preview.json) is the same output with a
fixed clock. Inspect its `table`, `preview`, `memoryApply`, and
`memorySnapshot` fields.

You can also open the ready-to-view [sample workbook](sample.xlsx) directly.
Its `Gap` and `Status` columns are formula-driven so changing an input value
shows how the output reacts; the compiler preview remains literal and
deterministic.

To use the normal CLI path and create a new local XLSX file:

```bash
node dist/cli.js compile examples/inventory-revenue/intent.json > /tmp/inventory-revenue-plan.json
node dist/cli.js validate /tmp/inventory-revenue-plan.json
node dist/cli.js apply-memory /tmp/inventory-revenue-plan.json
node dist/cli.js apply-xlsx /tmp/inventory-revenue-plan.json \
  --out /tmp/inventory-revenue.xlsx --apply
```

Expected statuses are `below` for sellable units, `watch` for daily revenue,
`watch` for fulfilled orders, and `met` for gross margin. The sample values
are illustrative, not a validated business forecast or a claim about a live
store.

This is local memory/XLSX artifact evidence only. It does not connect to
Excel Desktop or Google Sheets, recalculate formulas, ingest a live inventory
system, or establish production safety.
